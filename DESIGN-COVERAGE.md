# LLM Wire design coverage: Wave 3

This ledger distinguishes tested delivery from remaining design scope. A green local suite is evidence only for the named exercised paths. It does not establish full provider conformance or release readiness.

Provider reducer and local HTTP evidence is in the provider suites and test/llm_wire_integration_test.gleam. | Google GenerateContent text/tool profile                                                                              | Implemented for the admitted subset                                            | Request and continuation encoding, SSE reduction, text, tool calls, usage, structured-schema subset, refusal, output limit, malformed payload, and loopback tests are in src/llm_wire/google.gleam, src/llm_wire/api.gleam, and test/llm_wire_google_test.gleam. | SSE framing and provider fragmentation                                                                                | Implemented and tested for selected frames                                     | LF/CRLF, split CRLF/UTF-8, multiline fields, bounded event counts, representative frames at every byte boundary, and complete OpenAI/Anthropic/Google text interactions at every two-chunk byte split are covered by test/llm_wire_sse_test.gleam and test/llm_wire_provider_fragmentation_test.gleam. | OTP stream owner, deadlines, bounded progress, and cleanup                                                            | Implemented and tested for exercised paths                                     | The owner serializes reads, has one outstanding transport credit, bounds queued progress and body bytes, arbitrates read-timeout races, and cleans up on tested close, consumer death, terminal, disconnect, and shutdown paths. Evidence is in test/llm_wire_owner_test.gleam, test/llm_wire_wave1_regression_test.gleam, and the pool tests. The complete close/death/deadline/kill-at-every-state matrix remains Wave 5 release hardening, LLM Wire owner.                                                                                                                                                             |
| Optional Gun connection lease/reuse pool                                                                              | Implemented and tested as an explicit runtime path                             | llm_wire/pool starts a bounded GenServer; runtime.stream_with_pool and run_with_pool route PreparedCall-only requests through it. Leases are keyed by host/port/TLS identity, reused after healthy check-in, bounded per target/total and by waiter count, deadline-aware, and monitored for bridge/client/Gun process loss. Closing one stream does not cancel another. Pool lifecycle, reuse, owner death, FIFO, queue cap, timeout, and shutdown evidence is in test/llm_wire_pool_test.gleam. The no-pool API intentionally keeps one connection per request.                                                         |
| Strict 16 KiB response-header allocation bound                                                                        | Decision required                                                              | The local complete-header-in-one-write test proves that a 17 KB header is rejected. It does not prove a 16 KiB pre-allocation bound. Pinned Gun 2.6.0 checks its buffered header limit only if the terminator is absent; a complete block goes to handle_head/6 and Cowlib cow_http:parse_headers/1 before adapter-level size measurement. No second parser was added. The concrete decision is whether to take an upstream Gun/Cowlib change that checks the full block before assembly, or select a transport with that documented guarantee. Owner: LLM Wire maintainers; resolve before Wave 5 release acceptance.    |
