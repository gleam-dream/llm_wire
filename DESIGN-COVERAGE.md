# Wave 2 design coverage: `llm_wire`

This ledger replaces Wave 1 claims with evidence from the current working tree.
“Implemented and tested” means a named deterministic test or local HTTP/TLS
test exercises the behavior. “Partial” names the retained gap; it is not a
claim of acceptance.

| OTP ownership, queue, timeout, and cleanup                | Implemented and tested for exercised paths                                                         | Owner tracks one outstanding transport credit, bounded progress count/bytes, response body bytes, read identity plus owner-acknowledged timeout arbitration, consumer death, terminal cleanup, and idempotent close. A broad close/death race matrix is not present.                                                                                                                                                                                                                                           |
| HTTP/TLS adapter                                          | Gun 2.6.0, thin Erlang FFI, local tests                                                            | The low-level client and transport live under `llm_wire/internal`; each exported adapter boundary independently rejects remote plaintext, invalid paths/ports, malformed headers, and header injection before connecting. The adapter uses Gun HTTP parsing, one flow credit, `update_flow`, cancel, identity-only content encoding, redirect refusal, HTTPS peer/hostname verification, overall deadline, header/body/chunk caps, bounded error bodies, and `Retry-After` hints. Tests cover chunked transfer, redirect, compressed response rejection, 17 KB response-header rejection, response-body limit, setup stall, 429 hint, disconnects, pinned-CA success, and hostname failure. |
| Strict pre-allocation HTTP header limit                   | Partial                                                                                            | Gun is configured for 16 KiB and the adapter rejects parsed header lists above 16 KiB. Gun 2.6.0 checks its buffered header limit only when the header terminator has not arrived; a complete oversized block can therefore be allocated and parsed before the adapter rejects it. This transient allocation is bounded by the underlying socket receive, but does not prove a strict 16 KiB pre-allocation cap.                                                                                                                                                                                                                                                                            |
| Connection reuse                                          | Deferred                                                                                           | Each call opens and closes its own Gun connection. Reuse needs a separate connection manager/lease owner and pool lifecycle contract; the current stream owner does not share sockets across calls.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Sinal lifecycle observations                              | Implemented and tested for schema/redaction                                                        | Typed stages cover prepared, request sent, first progress, terminal, cancelled, deadline, and cleanup. Metadata contains only stage/provider/fixed outcome; `lifecycle_observation_contains_only_fixed_metadata_test` captures the event.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Anthropic Gleam streaming reuse                           | Evaluated and rejected for production                                                              | `test/anthropic_gleam_reuse_evaluation_test.gleam` checks its published request builder and incremental handler. The request builder is usable, but the public state retains every decoded event (40 input events produced 40 retained events), and malformed decoded events are filtered instead of failing. The dependency is dev-only.                                                                                                                                                                                                                                                                                                                                                   |
| Google Gemini                                             | Deferred to Wave 3 with continuation evidence                                                      | Generate Content uses `contents`/`parts` and a provider-specific streaming reducer. More importantly, the documented `FunctionCall.id` is optional for legacy models, while the current continuation contract carries exact call identity into function results. Gemini 3 documents IDs as always returned, so Wave 3 can either constrain the supported model profile or define a safe local correlation representation. References and details are in `WAVE-2-REPORT.md`.                                                                                                                                                                                                                 |
| Realtime/WebSocket, multimodal messages, provider caching | Backlog                                                                                            | No Wave 2 implementation or test claim.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## Required follow-up

- Wave 3: Google provider profile, strict pre-allocation HTTP header enforcement
  (or a transport with that guarantee), broader process-race coverage, duplicate
  JSON-member coverage, and full source-case inventory for selected oracles.
- Wave 4: shared connection reuse/pooling behind a distinct connection/lease
  owner; current calls still open and close a connection per request.
- Wave 5: multimodal and realtime transport families.
