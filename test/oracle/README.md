# Oracle inventory and test derivation ledger

This is a selected behavioral inventory, not a blanket ReqLLM parity claim. ReqLLM is a read-only behavioral reference; it is not a dependency and its suite was not run. Only the exact cases named below are selected. Other cases in these source files, and the rest of ReqLLM, are excluded from this slice unless named as an explicit exclusion.

## Pins and provenance

- ReqLLM v1.24.0: annotated tag object 29f855513c327ec5630a16215531ad2d459ae56e; tagged commit fd9e079fddf253e9b719b2d2c6920f4306592809; Apache-2.0, from the upstream LICENSE file.
- Jido AI v2.3.0 is not paired with ReqLLM v1.24.0: its lockfile uses ReqLLM 1.17.1. Jido is background architecture context only, not a Wave 3 oracle.
- The Google adapter is based on official API documentation, not ReqLLM parity: [Generate Content API](https://ai.google.dev/api/generate-content), [function calling](https://ai.google.dev/gemini-api/docs/function-calling), [structured output](https://ai.google.dev/gemini-api/docs/structured-output), [Gemini 3](https://ai.google.dev/gemini-api/docs/gemini-3), and [thought signatures](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures).
- The standard Erlang JSON boundary uses OTP's documented JSON decoder callbacks and encoder: [OTP json module](https://www.erlang.org/doc/apps/stdlib/json.html).
- Resolved adapter/runtime versions are Gun 2.6.0 and Cowlib 2.20.0 (ISC notices in their resolved package trees), gleam_json 3.1.0, and OTP 28. anthropic_gleam 0.1.1 (MIT) remains development-only. ReqLLM source was inspected locally; no upstream test command was run.

## Explicit exclusions from the selected ReqLLM comparison

- The other cases in context_tool_continuation_test.exs are excluded where they require ReqLLM Context/message serialization, live-process serialization, result-name fields, provider-native tool execution, or Context values without assistant tool calls. LLM Wire instead binds opaque continuation to PreparedCall, validates IDs, and keeps application execution with the caller. Invalid result content schema parity is not claimed because ToolResult is currently a string payload.
- Other cases in sse_test.exs that exercise ReqLLM's convenience JSON passthrough, malformed-data preservation, SSE metadata projection, empty-stream helpers, or very-large-JSON fixture are excluded. LLM Wire frames SSE only; each provider reducer parses its own JSON with the standard Gleam JSON boundary.
- Metadata-only cleanup, lazy enumerable wrappers, callback invocation, response-ID generation, legacy Response conversion, provider builtin classifiers, and simultaneous metadata collection from stream_response_test.exs are excluded. They describe ReqLLM's response wrapper and metadata handle, which LLM Wire does not expose. Its owner serializes reads instead of permitting parallel consumers.
- The remaining cases in integration/streaming_orchestration_test.exs that start streams through ReqLLM model/provider discovery, Finch, provider configuration failures, or idle metadata-handle policy are excluded; these are not part of the PreparedCall/Gun public contract.
- The remaining retry_test.exs case, “passes Finch checkout options through to the stream transport,” is excluded because Finch pool options do not apply to the Gun adapter.
- provider/chunk_accumulator_test.exs was consulted in Wave 2 for text, thinking, tool-fragment, finish, and usage laws but is not selected as a Wave 3 oracle file: ReqLLM's accumulator supports image ordering, arbitrary chunk metadata, annotations, logprobs, UUID synthesis, and legacy message projections beyond this contract. Related common evidence is local and independently named in the provider reducer tests; ReqLLM accumulator parity is not claimed.
- The external ReqLLM integration suite, real providers, credentials, retries against remote APIs, and its unselected source cases were not run.

## Local Wave 3 evidence beyond the ReqLLM selection

- test/llm_wire_provider_fragmentation_test.gleam sends each complete text interaction through every byte boundary, preserving adapter semantics across fragmentation.
- test/llm_wire_google_test.gleam covers local GenerateContent text, tool, continuation, refusal, token limit, usage, structured schema admission, and malformed payloads. thoughtSignature is rejected explicitly because the provider-neutral continuation cannot retain its required opaque state.
- test/llm_wire_pool_test.gleam covers sequential reuse, concurrent stream isolation, owner death, deadline-bound waiters, FIFO checkout, bounded queue, invalid limits, and shutdown of active leases.
- test/llm_wire_integration_test.gleam sends a complete 17 KB response-header block in one TCP write and observes rejection. This is post-parse rejection, not a strict allocation bound; the dependency finding is recorded in DESIGN-COVERAGE.md and WAVE-3-REPORT.md.
