# Send files, optional answer fields and unstored responses to OpenAI

<a id="adr-0021"></a>

## Decision and alternatives

- **The problem.** dash-crm moves every agent from Gemini to OpenAI's Responses API, and the owner ruled on 2026-11-19 that LLM Wire closes three gaps itself instead of the application working around them or forking.
  - A PDF had no part of its own. dash-crm sent it as `InlineImagePart` with `application/pdf`, which Gemini reads as inline data and OpenAI refuses as an `input_image`.
  - OpenAI's and Anthropic's strict structured output refused any record with an optional field, while dash-crm's agent codecs use `codec.optional_field`.
  - OpenAI keeps every response for 30 days unless the request sends `store: false`, and the adapter had no way to send it.
- **A file part.** `message.Content` gains `InlineFilePart(mime_type:, file_name:, base64_data:)`, a document the provider reads as a file.
  - **OpenAI:** `{"type": "input_file", "filename": file_name, "file_data": "data:<mime_type>;base64,<data>"}`. Any media type other than an image is passed through; OpenAI decides which it reads.
  - **Google:** `inlineData` with `mimeType` and `data`, as for an inline image. Gemini's `inlineData` has no name field, so the file name is not sent.
  - **Anthropic:** a `document` block with a `base64` source and the file name as its `title`. Anthropic's base64 document source takes only `application/pdf`, so preparation refuses any other media type that is not an image with `InvalidRequest(FileTypeUnsupported(media_type))`.
  - The message codec stores it as `{"type": "inline_file", "mime_type", "file_name", "data"}` in the same `llm_wire.message.v1` format.
- **A file part with an image media type is sent as the provider's image**, exactly as an `InlineImagePart` with the same media type and data: OpenAI `input_image` with a data URL, Anthropic an `image` block, Google `inlineData`. A media type is an image when its type, compared without case and parameters, is `image`.
  - dash-crm stores photos and PDFs as one kind of original and asked, after its design review, to send them all as one kind of part, leaving the provider part to LLM Wire. The provider's wire form is the library's knowledge, so the choice belongs here.
  - The file name is not sent for an image. No provider has a field for an image's name, and Google already sends no name for any file, so the name is a label the provider may use, not a requested feature that is dropped.
  - Rejected: refusing an image in a file part (an earlier draft of this decision). It kept one wire form per part kind, but every caller with mixed attachments would repeat the same media-type branch.
  - Rejected: sending an image as `input_file`. OpenAI documents file inputs for documents, so the image would fail at the provider.
  - `InlineImagePart` keeps its behavior: its media type is not checked, so the PDF-as-image form Gemini accepts still reaches Gemini unchanged.
- **Optional fields in strict output.** OpenAI and Anthropic projections send an optional property as required and nullable: its name joins `required` and its schema becomes `{"anyOf": [{"type": "null"}, schema]}`, Blueprint's own nullable form. A property already nullable keeps its schema and only joins `required`. The rule applies at every depth: nested records, list items and union payloads. Google's projection is unchanged, because `responseJsonSchema` honours `required`.
- **The answer is cleaned before it is decoded.** For every provider, custom adapters included, the parsed answer is walked against the output codec's schema, and a `null` member is removed where the property is optional and its schema admits no `null` (it is neither nullable nor `codec.value()`). The cleaned value is then validated against the original contract and decoded by the original codec.
  - `Answer.text` is the cleaned JSON when a member was removed, written compactly with exact numbers, and the provider's text unchanged otherwise. dash-crm's agent library decodes `Answer.text` itself with the original codec, so the text must be what that codec accepts.
  - `InvalidOutput.raw_output` is cleaned the same way when the text is JSON, and is the provider's text when it is not. dash-crm hands that text to Fabric as the model's answer, and Fabric's correction turn decodes it with the original codec, so a `null` the codec refuses must not survive there either. The text still shows what the model answered; only `null` members that mean absence are gone.
  - The cleaning is not tied to the strict projection. A `null` where the caller's schema allows only absence can mean nothing but absence, and the original codec would refuse it, so removing it is safe for any provider.
  - A property declared nullable keeps its `null`: `optional_field` with `nullable` decodes it as `Some(None)`.
  - Rejected: decoding `null` as absent inside the codec. Blueprint's `optional_field` rejects `null` by design, and the codec belongs to the caller.
  - Rejected: requiring callers to declare `nullable` fields for strict providers. Their codecs also describe stored data and other providers.
- **Unstored OpenAI responses.** `openai.with_store(options, store)` sends `"store": store` on every Responses request. Without it the field is left out, so OpenAI's default (stored) applies, as before.
  - The default stays unchanged because flipping it would change every existing caller's stored data and response retrieval without a compile error, in a release that Fabric's `< 0.3.0` requirement admits.
  - LLM Wire replays the whole conversation and never reads a stored response, so the library itself needs no stored response. Whether `false` should become the default is left as a pending ruling for the next breaking release.
- **OpenAI function tools are sent with `"strict": false`.** Without the field, the Responses API normalizes a tool schema into strict mode when it can and falls back to non-strict otherwise, so whether an optional argument stayed optional depended on OpenAI's normalization. With `false` the schema the model sees is the caller's schema as given: an optional argument stays optional, and `codec.value()` stays admitted.
  - The arguments reach the caller exactly as the model wrote them, and are checked locally against the tool's contract, as on every provider: an invalid call fails the response or becomes an `InvalidArguments` issue under `ReportInvalidToolCalls`.
  - Rejected: strict tools with the optional-to-nullable projection and `null` removal on arguments. Arguments are replay evidence: Gemini's signed replay data is verified against the turn's calls, and OpenAI and Anthropic replay them verbatim, so rewriting them would put the delivered calls out of step with what the provider recorded. Strict mode would also refuse tools that take `codec.value()`, so each tool would need its own mode.
  - The cost is that OpenAI does not constrain the arguments to the schema; a non-conforming call is visible as an invalid call rather than prevented.
- **OpenAI's encrypted reasoning is not carried, by decision.** Under `store: false`, OpenAI returns reasoning items with `encrypted_content` only when the request sends `include: ["reasoning.encrypted_content"]`, and accepts them back before the tool calls they preceded. The owner ruled on 2026-11-19 that LLM Wire does not carry them, now or later: the request never asks for the include, the assistant turn keeps no reasoning item, and the encoder replays tool calls as `function_call` items with `call_id` only, without an item `id` or `previous_response_id`. OpenAI therefore reads them as new input rather than references to stored items: an unstored tool round replays without the earlier reasoning items, and the model loses that reasoning. A 400 for a missing reasoning item would need the calls to reference stored items, which they do not. The `openai-tool-round` recording on `gpt-6.2-sol` shows OpenAI accepting a follow-up whose call carries `call_id` only. At medium effort the model reported no reasoning tokens on either prompt tried, so that round had no reasoning item to leave out; a round that drops one is not recorded.
- **The version.** These changes ship as 0.2.1.
  - `message.Content` and `error.RequestProblem` each gain variants. Both are documented to gain variants in a minor release and to be matched with a `_` arm, so a `case` written that way compiles unchanged.
  - A `case` over either without a `_` arm stops compiling; neither Fabric 0.4.0 nor dash-crm has one.
  - No signature changes. A codec with an optional field that preparation refused before now prepares.

## Evidence and limits

- The wire forms follow the providers' documentation: OpenAI's file inputs for the Responses API (each file and all files of a request under 50 MB), its structured outputs guide (every property required, `additionalProperties: false`, optional emulated as a union with `null`) and its statement that responses are stored for 30 days unless `store` is `false`; Anthropic's PDF support (`document` with a `base64` source); Gemini's `inlineData`. Five live scenarios on `gpt-6.2-sol`, recorded on 2026-11-19 with `store: false`, replay offline: a PDF file part read into a structured answer (`openai-file-pdf`), an optional field the model answered with `null` and one it filled (`openai-optional-null`, `openai-optional-value`), a plain answer (`openai-store-false`) and a tool round of two exchanges (`openai-tool-round`). No cassette holds a key or an account header.
- **The tool round found a reducer defect, fixed here.** OpenAI streams `response.function_call_arguments.done` and then `response.output_item.done` for every function call. The reducer treated both as the call's completion and failed every real OpenAI tool call with "Duplicate tool block completion"; the scripted replies of `llm_wire/testing` never sent the first event, so no test caught it. `response.function_call_arguments.done` now only confirms the arguments: they must equal the streamed ones, or supply them when no delta came, and `response.output_item.done` alone closes the call. The scripted replies send both events, as OpenAI does.
- Request bodies are bounded by `limit.RequestBytes`, 1 MiB by default. A caller sending files raises it with `llm_wire.with_limit`; OpenAI's 50 MB request cap is the provider's to enforce.
- `test/llm_wire_file_part_test.gleam` pins each provider's file encoding, Anthropic's literal media types, the refusals and the codec round trip. `test/llm_wire_optional_output_test.gleam` pins the projection for nested records, list items, union payloads and nullable properties, and the cleaning across all three providers. `test/llm_wire_openai_store_test.gleam` pins `store`, and `test/llm_wire_openai_tool_strict_test.gleam` pins the non-strict tool and verbatim arguments.
